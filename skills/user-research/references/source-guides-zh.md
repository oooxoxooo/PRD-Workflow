# 中文信源采集操作手册（source-guides-zh）

本手册是 voc-playbook 模式 2（主动采集）的配套操作手册：模式 2 判定用中文互联网公开信源时，按本手册逐平台执行采集。voc-playbook 管"提取、综合、标注、回传"，本手册管"去哪找、找什么、读哪类内容、各平台有什么坑"。

**全局铁律一（幻觉 URL 一票否决）**：禁止输出本会话未实际访问过的 URL。每访问一个信源，立即把该 URL 记入本次会话的"已访问清单"，后续报告只允许引用清单内的 URL；记不清 = 没访问过 = 不许写。本手册中出现的所有搜索词均为示范模板，方括号占位符（[品类]、[竞品名]）执行时必须替换为实际词；手册本身不含、也不许你在产物中编造任何"典型 URL"。

**全局铁律二（脱敏前置）**：所有采集材料进 voc_pipeline.py 脱敏管道后才可分析。逐条摘录的原声连同信源名与日期落盘为中间文件，先跑脚本脱敏（手机号/身份证/邮箱/银行卡号/中文姓名的正则掩码，不可逆），再做语义提取；禁止绕过脚本直接处理原始文件，脚本脱敏后仍须人工复查一遍无个人身份信息残留。

## 按 ICP 类型选信源（速查表）

先用一句话确认 ICP，再从下表取前 2-3 个信源作为主战场，其余作交叉验证。采集下限沿用 voc-playbook：每个主题至少 2 个独立信源。

| ICP 类型 | 首选信源 | 交叉验证信源 | 采集要点 |
|---|---|---|---|
| B2B 软件 | 知乎、即刻 | V2EX、微博 | 搜"选型""替代""劝退"类词，关注采购决策链上的真实吐槽与续费犹豫 |
| 开发者工具 | V2EX、即刻 | 知乎、B站 | 关注集成成本、文档质量、数据安全顾虑、订阅制反感；技术原声可直接进需求文档 |
| 消费 App | 应用商店评论、小红书 | B站/抖音评论区、微博 | 差评读失效时刻，小红书读场景化用法，评分两极分化的中间地带信息密度最高 |
| 电商消费 | 什么值得买、小红书 | 微博、B站/抖音评论区 | 关注"值不值"、价格锚点、决策因子排序；价格敏感度信号密度最高的场景 |
| 企业服务 | 知乎、微博 | 即刻、V2EX | 关注实施/售后吐槽、招投标语境下的对比表述、行业舆情事件 |

## 平台操作卡

每张卡固定四节：怎么找到内容 → 什么内容信号强 → 提取什么 → 该平台特有偏差。提取对照 voc-playbook 的统一提取六要素（JTBD 三层 / 痛点 / 触发事件 / 期望结果 / 原声词汇 / 备选方案），各卡只写该平台侧重点。

### 1. 知乎

**怎么找到内容**

- 搜索引擎侧：`site:zhihu.com [品类] 推荐`、`site:zhihu.com [竞品名] 是一种怎样的体验`、`site:zhihu.com [竞品名A] [竞品名B] 哪个好`。
- 站内入口：搜索框输入品类词后按"赞同数"或"时间"排序；问题页先看"关注者数/被浏览数"判断问题热度。
- 长尾入口：从高票回答的评论区顺藤摸瓜到其他相关问题（"类似问题"侧边栏）。

**什么内容信号强**

- "如何评价 X"问题下的长回答：通常包含完整使用周期叙述，是六要素最全的矿层。
- 反对票高、评论区吵翻的回答：争议信号本身即洞察——分歧点往往就是品类未满足的需求裂缝。
- "X 有哪些缺点/劝退点"类问题：痛点与失效时刻的直接来源。
- 评论区往往比回答正文更真实：回答可能有立场修饰，评论区是即时反应。
- 写在付费咨询/好物推荐卡片之外的回答：带带货链接的回答置信度降一档处理。

**提取什么**

- 侧重点：备选方案对比（知乎回答最爱列"A vs B vs C"对比表）、痛点（"劝退"理由逐字收）、JTBD（"我用 X 主要是为了…"句式）。
- 期望结果常出现在"理想中的工具应该…"类段落，单独收。

**该平台特有偏差**

- 样本偏高学历、偏一二线城市、偏男性；回答写作有表演性（"谢邀"文体），情绪表达被文体稀释，强度判断打八折。
- 软文与机构号渗透严重：识别特征为行文模板化、通篇无具体使用细节、结尾导向私信或链接——此类内容不采。
- 老回答时效差：3 年前的"如何评价 X"描述的可能已是另一个产品，超过 12 个月的材料单独标注日期。

### 2. 小红书

**怎么找到内容**

- 站内搜索框输入品类词，**先看下拉联想词**——下拉词是真实用户搜索需求的直接暴露，本身就是#原声词汇素材。
- 搜 `[品类] 避雷`、`[品类] 踩坑`、`[竞品名] 好用吗`、`[竞品名] 平替`、`[品类] 测评 真实`。
- 从一篇高赞笔记的评论区"求链接/求平替"顺藤到相关笔记与合集。

**什么内容信号强**

- "避雷/踩坑/拔草"类笔记：痛点金矿，且通常带具体场景（"出差用了一次就…"）。
- 笔记评论区问"求链接""好用吗""和 X 比哪个好"的层：这是评估期用户的实时提问， objections 与对比对象的直接来源。
- "自用半年/一年真实测评"类笔记：深度体验，失效时刻与期望结果密度高。
- 同一博主"先种草后拔草"的时间线：触发事件的完整证据链。

**提取什么**

- 侧重点：场景化用法（用户拍照展示的真实使用环境=JTBD 的情境层证据）、价格敏感表述（"这个价位还不如…""学生党劝退"）、备选方案（"平替"一词本身就是备选方案信号）。
- 原声词汇重点收口语化表述：小红书语言是后续文案取材的最佳语料。

**该平台特有偏差**

- 样本偏一二线年轻女性；内容有强种草文化，"素人感"可能是商业投放伪装——识别特征：多账号同图同文案、评论区清一色好评无追问，此类不采。
- 图片修饰文化：展示的使用场景可能是摆拍，场景判断注明"图文自述，未验证"。
- 情绪表达夸张（"哭了""救命""绝绝子"），强度判断需对平台语言习惯做归一化。

### 3. 应用商店评论（App Store 中国区 / 各大安卓市场）

**怎么找到内容**

- App Store 中国区：进入目标 App 页面，评论按"最低评分"排序先读，再按"最新评价"排序读近期失效时刻。
- 安卓侧：华为、小米、OPPO、vivo 应用商店与应用宝各自独立——同一 App 在不同市场的评论人群不同（渠道机用户结构差异），至少采两个市场。
- 搜竞品名直接进入其评论页，竞品差评 = 你的机会清单。

**什么内容信号强**

- 1-2 星差评：失效时刻（"更新后就闪退""突然开始收费"）、功能缺失、广告抱怨的集中地。
- 3 星评论：最诚实——"基本够用但是…"句式里是真实的取舍逻辑，信息密度通常最高。
- "从 X 转来"类评论：替换动因与触发事件的直接证据（"以前用 X，自从它开始…就换了这个"）。
- 开发者回复下的用户追加：售后体验的真实信号。
- 差评中反复出现的具体版本号/机型：产品缺陷的可验证线索。

**提取什么**

- 侧重点：JTBD（"我用它来…"句式逐字收）、失效时刻（"自从 X 版本之后…"）、对比对象（每条提及的竞品名都计入备选方案字段）。
- 触发事件常藏在"更新后""换手机后""开始收费后"类时间状语里，单独标记。

**该平台特有偏差**

- 评论者偏向极端意见（极好/极坏），沉默的大多数不在样本里——结论措辞限定为"评论者中"，不外推为"用户中"。
- 刷好评与竞对刷差评均存在：识别特征为短句模板化、集中在某几天爆发、五星带无关关键词堆砌——按日期分布异常过滤。
- 安卓各市场互不打通，同一用户的愤怒可能重复出现在多个市场——跨市场去重后再计频次。

### 4. 微博

**怎么找到内容**

- 站内搜索 `[竞品名] 难用`、`[品类] 求推荐`、`[竞品名] 崩了`；切"实时"标签拿最新抱怨。
- 热搜与文娱榜：品牌/消费品的舆情事件入口，事件发酵期（24-72 小时）是情绪信号最密集的窗口。
- 超话社区：进入品牌或品类超话，看"精华帖"与粉丝互助问答。

**什么内容信号强**

- 实时抱怨短微博："X 又崩了""被 X 气死"——情绪强度与失效时刻信号，但上下文稀薄，只做主题计数不做动机推断。
- 热搜事件下的转评：舆情期用户的真实立场分层（粉/黑/路人），适合品牌类研究。
- 超话里的"求助帖"与"教程帖"：JTBD 与使用摩擦点。
- 大 V 吐槽的转发区：比原微博更接近路人真实看法。

**提取什么**

- 侧重点：情感层 JTBD 与情绪强度（微博是情绪信号最强、上下文最弱的信源）、触发事件（舆情事件的起因表述）。
- 原声词汇收短句口语与网络用语；六要素中痛点、期望结果以外的字段微博里常"未提及"，标"未提及"不脑补。

**该平台特有偏差**

- 水军与营销号噪音全平台最高：采信前看主页历史（注册时长、历史发文是否同品类、语气是否模板化）；无法判断账号性质的评论不采。
- 热搜机制可购买，热搜在场 ≠ 自然舆情；以普通用户原创微博为准，媒体通稿不采。
- 表达文化夸张且跟风（玩梗、复读），单条情绪强度参考其他平台打六折；同一话题下重复玩梗的句子只记一次。

### 5. 什么值得买

**怎么找到内容**

- 站内搜索 `[品类]`、`[品类] 横评`、`[竞品名] 值不值`；按"最热"与"最新"各扫一遍。
- 商品页的"值/不值"投票与评论区：价格讨论的集中地。
- "好价"频道历史价格帖：价格锚点与促销敏感度的直接证据。

**什么内容信号强**

- 深度横评长文：决策因子排序的金矿（作者会逐项比较：材质、续航、售后、价格），JTBD 功能层信息最全。
- 商品爆料评论区："这个价不值""等 618""比 X 便宜时才值得入手"——价格锚点与购买触发条件的直接原声。
- "值/不值"投票比例本身：品类接受度的粗指标（仅作背景，不进六要素）。
- 晒单帖的使用环境照片与"缺点也说一下"段落。

**提取什么**

- 侧重点：价格锚点（用户口中的"合理价位""超过 X 就不值"）、决策因子排序（横评中各项被提及的先后顺序与权重）、备选方案（"这个价位不如买 X"）。
- 触发事件常出现在"因为 [旧物坏了/搬家/孩子出生] 所以研究了一圈"类开篇，整句收。

**该平台特有偏差**

- 样本偏价格敏感型理性消费者、偏男性数码家居品类；时尚美妆等品类信号弱。
- 作者有返利与推广分成动机：带推广链接的好价帖与软文评测置信度降一档，纯晒单无链接帖优先采。
- "等等党"文化导致价格表述系统性偏低——用户口中的"合理价位"是愿望价不是成交价，注明这一点。

### 6. 即刻

**怎么找到内容**

- 站内搜索 `[竞品名]`、`[品类] 替代品`、`求推荐 [品类]`；关注"产品经理""互联网那点事"等圈子。
- 搜 "X 的替代品" 话题帖：竞品全景与替换动因的集中讨论。

**什么内容信号强**

- "X 的替代品"类话题：备选方案字段最密集的信源，一帖收齐竞品清单。
- 产品经理/独立开发者自曝 workflow 的动态："我的 [工作场景] 工具栈是…"——JTBD 与工具组合的完整叙述。
- 新工具上线的即友测评：早期采用者的第一反应，领先于大众舆情 3-6 个月。
- 行业动态讨论区对竞品融资/翻车事件的评论：决策链视角的顾虑（"这种商业模式活不久"）。

**提取什么**

- 侧重点：备选方案（工具栈清单整段收）、JTBD 社会层（即刻用户爱谈"什么人用什么工具"的身份叙事）、顾虑（隐私、数据安全、订阅疲劳）。
- 原声词汇是互联网从业者的行话语料，适合做 B2B/开发者产品的文案取材。

**该平台特有偏差**

- 样本严重偏互联网从业者与早期采用者，信号前沿但人群极客化——结论必须注明"样本来自即刻，偏早期采用者"，禁止外推大众市场。
- 圈子熟人文化：互夸与利益相关（作者认识开发者）常见，涉及具体产品的彩虹屁降一档置信度。
- 样本量小：单一话题可能只有几十条讨论，容易跌破 5 个独立数据点的最小样本量——不足时只进研究缺口清单。

### 7. V2EX

**怎么找到内容**

- 站内搜索（或搜索引擎 `site:v2ex.com [品类]`）：重点扫"问与答"节点的求推荐帖、"分享创造"节点的新品发布帖、"全球工单系统"节点的吐槽帖。
- 搜 `求推荐 [工具类别]`、`[竞品名] 替代`、`[品类] 自建 还是 买`。

**什么内容信号强**

- "问与答"节点的工具求推荐帖：发帖人自述需求=JTBD 原声，回帖推荐=备选方案全景，回帖劝退=顾虑清单。
- "分享创造"节点竞品发布帖的评论区：开发者同行的第一反应，技术选型顾虑（数据安全、开源与否、订阅制反感）表达最直白。
- "全球工单系统"节点：对各厂商服务/产品的实名吐槽，失效时刻与售后痛点密度极高。
- 关于定价模式的讨论帖：V2EX 对订阅制、涨价、功能阉割的反感是稳定信号。

**提取什么**

- 侧重点：顾虑（数据安全/隐私/锁定风险，逐字收）、备选方案（自建/开源替代是高频合法选项，"我自己写了个脚本"必须记录）、技术用户的原声词汇（可直接进需求文档）。
- 触发事件常是"厂商作恶"类事件（涨价、关停、隐私丑闻），事件名与日期一起记。

**该平台特有偏差**

- 样本偏一线城市开发者与技术从业者；表达风格毒舌直接，情绪强度读数偏高但真实性也高。
- 强反商业氛围：对一切收费与营销行为的天然敌意是平台文化，不一定是品类真实态度——与其他信源交叉后再定强度。
- 技术选型偏好（开源优于闭源、自建优于 SaaS）是人群属性而非市场全貌，结论注明人群结构偏向。

### 8. B站 / 抖音评论区

**怎么找到内容**

- B站：搜 `[品类] 测评`、`[竞品名] 使用体验`、`[品类] 教程`；按"最多点击"与"最新发布"各扫一轮，优先读 10 分钟以上的深度测评与"用了半年说说感受"类视频。
- 抖音：搜 `[品类] 避雷`、`[竞品名] 真实测评`；评论区按热度读，重点看被顶上去的追问。
- 两平台都搜 `[竞品名] vs [竞品名]` 对比视频：评论区是评估期用户的实时辩论场。

**什么内容信号强**

- 教程类视频评论区的时间戳提问（"03:25 这一步我这怎么没有"）：工作流困惑点的精确定位，比任何问卷都准。
- "用了半年说说感受""真实测评无广"类视频及其评论区：深度体验与失效时刻。
- 弹幕中的集体反应时刻（满屏"真实""劝退"）：情绪强度的粗刻度。
- 对比视频评论区的站队与反驳：各竞品的真实口碑分布。

**提取什么**

- 侧重点：工作流困惑点（时间戳提问逐字收，直接映射 JTBD 功能层的摩擦）、期望结果（"要是能 X 就好了"句式）、场景化用法（视频展示的真实环境）。
- 弹幕与评论的情绪词只做强度参考，不进原声词汇字段（弹幕非完整表述）。

**该平台特有偏差**

- 弹幕礼仪文化导致表达夸张（"封神""垃圾"都是惯用语），情绪强度打七折；玩梗内容不采。
- 视频作者多有商单（标注"合作"或未标注的软广）：商单视频本身的观点不采，但其评论区真实反应可采。
- 抖音评论区水军与控评常见：同一评论被大量复制、账号头像昵称同质化即弃；B站用户偏年轻学生群体，付费能力表述系统性偏低。

## 采集记录表

所有信源的采集结果汇入同一张流水表，一行一条原声，禁止凭记忆复述——摘录即复制原文：

| 来源 | 日期 | 原声 | 标签 | 备注 |
|---|---|---|---|---|
| [平台+帖子标题] | [YYYY-MM-DD] | [逐字摘录，错别字口头禅保留] | [#痛点 #触发 #期望结果 #原声词汇 #备选方案 #顾虑 #竞品，可多标] | [上下文、账号性质判断、置信度线索] |

执行要点：

- 标签从七个固定值中选，可多标；没有对应标签的好材料用备注说明，不硬贴。
- 每访问一个信源，先把 URL 记入本会话"已访问清单"，再开始摘录；清单外的 URL 不得出现在任何产物中。
- 采集 20-30 条后模式自现：跨信源重复出现的原声是最高置信度信号（对照 voc-playbook 置信度三级，3 个及以上独立信源且用户主动提及方可标 High）。
- 同一用户跨平台重复内容去重后再计频次，防止一人多贴虚增信源数。
- 采集满额后整表过 voc_pipeline.py 脱敏管道，再进入六要素提取。

## offline 兜底

无网、平台反爬或登录墙阻断时，执行降级路径，不许硬闯也不许假装访问过：

1. 在会话记录中逐信源标注 💡 降级说明（"该信源未实际访问，以下不含其数据"），绝不假装访问过。
2. 退回模式 1：请用户提供导出材料（评论导出、问卷、工单、客服记录），按 voc-playbook 模式 1 的材料类型表执行分析。
3. 最终产物开头显著位置标注"采集环节降级"及降级范围（哪些信源缺失、改用何种替代材料）。
4. 降级不影响其余硬约束：幻觉 URL 铁律、置信度三级、脱敏前置、四字段回传逐条照旧执行。
5. 产物路径、回传格式不变：落盘 `research/user-[slug].md`，经 SendMessage 向主理人 allan-team-lead 回传四字段——产物路径 / 关键结论（≤5 条）/ 未决问题 / 建议下一阶段输入。
